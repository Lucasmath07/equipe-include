# equipe-include

Repositório criado para a atividade prática de **Git e GitHub**, que simula um ambiente de desenvolvimento de software colaborativo.

## 🎯 Objetivo

Praticar o fluxo de trabalho em equipe com Git e GitHub, aprendendo a:

- Criar e gerenciar um projeto em um repositório compartilhado
- Trabalhar com _branches_
- Submeter alterações por meio de Pull Requests
- Realizar revisões de código (_code review_)
- Resolver conflitos de _merge_

## 📄 O que a equipe vai construir

Um documento Markdown chamado [`EQUIPE.md`](./EQUIPE.md), que funciona como uma página de perfil de todos os membros. Cada integrante adiciona a sua própria seção ao arquivo.

## 👥 Estrutura da equipe

| Papel            | Quantidade | Responsabilidade                                                          |
| ---------------- | ---------- | ------------------------------------------------------------------------- |
| Líder/Mantenedor | 1          | Cria e mantém o repositório e é o único a fazer _merge_ dos PRs na `main` |
| Colaboradores    | 4          | Desenvolvem seus perfis em branches separadas                             |

## 🌿 Convenção de branches

Cada membro trabalha em uma branch própria, criada a partir da `main`:

```
feature/perfil-seu-nome
```

## 📝 Convenção de commits

Usamos mensagens claras que descrevem a alteração, por exemplo:


```
docs: adiciona perfil de Fulano
```

## 🔄 Fluxo de trabalho

1. Clonar o repositório
2. Criar uma branch `feature/perfil-seu-nome`
3. Editar o `EQUIPE.md` adicionando seu perfil
4. Fazer commit e push da branch
5. Abrir um Pull Request para a `main`
6. Revisar o PR de pelo menos um colega
7. O líder faz o _merge_ dos PRs

## 🤝 Membros

Veja os perfis completos em [`EQUIPE.md`](./EQUIPE.md).
